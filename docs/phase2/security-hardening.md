Status: continuing on active branch `arena/81ef53da-balancify`; PR #18 is merged as `a1ec9b0`. Pinned x64 and ARM64 WDK CI compile/link, PE architecture/mitigation/unsigned-status checks, and INF contract tests passed in push run `39799406998`; signed install, Driver Verifier, HVCI, VM, and packet-path validation remain pending.

## Done

- **Crypto allowlist + exact-pin audit** (C2/C4): `tools/ci/audit-deps.sh` checks allowlist (chacha20poly1305=0.11.0, x25519-dalek=2.0.1, blake2=0.10.6, hkdf=0.12.4, getrandom=0.2.15, zeroize=1.8.1) + exact-pin, fails on anything not on list, checks PassThrough literal, checks Cargo.lock if present
- **PassThrough cannot ship** (Phase-4 CI audit): `PassThrough` cipher is test-only, must never ship, audit fails if literal found in release build
- **No third-party kernel component in data path** (C2): only NDIS + WDF, no Wintun unless exception file exists (ADR-0009)
- **AEAD with AAD binding**: ChaCha20-Poly1305, header bound as AAD, nonce separated by frame kind/path/sequence/salt/key, FlowData and keepalive counters avoid nonce reuse, 16-byte tag only overhead, every bit position refused, wrong-length key refused, 20-payload stream end-to-end (10 tests in `crates/crypto/src/lib.rs`)
- **Tunnel control authentication and replay resistance**: ACK/probe/probe-reply/keepalive require session-bound AEAD authentication; each control kind has a bounded replay window, stale cumulative ACKs are rejected, and the service applies ECN/liveness effects only after verification. Session allocation is deferred until authentication, and unauthenticated or replayed frames cannot refresh receiver or relay idle timers. Forged-control, session-allocation, and relay-idle regression tests cover these invariants.
- **Bounded FlowData repair** (ADR-0036): retain eligible plaintext up to the configured byte/entry caps until authenticated FlowAck; retry once by default on an alternate path after RTO using the same session/sequence and the reinjected flag. Receiver replay rejection prevents duplicate payload delivery while generating another FlowAck, so lost acknowledgments are repaired too.
- **Noise_IK handshake** (Sec.9.2): both sides derive same two keys, pinned relay identity authenticates, every byte of flight 1 authenticated, prologue binds context, initiator static travels encrypted, fresh ephemeral gives fresh session, flights out of order refused, truncations refused, the relay requires an exact 8-byte session-id request, refuses an active session-id collision without replacing the existing session, and the authenticated response must echo that id exactly before keys are installed. Handshake failure logging is capped at one line per second; malformed, replayed, rate-limited, unknown-session, and refused handshake/tunnel traffic increment the reject counter; per-IP rate-limit tracking is capped at 4096 source IPs with oldest-window eviction; relay startup fails closed when the pinned-client store is corrupt or unreadable instead of silently disabling pinning; pinning is enforced both sides and the replay cache rejects a repeated first flight. Forwarding always uses the exact session's upstream socket; there is no cross-session peer-address fallback. Connected per-session UDP egress sockets accept replies only from the configured upstream endpoint. Invalid upstream addresses (including port zero and unspecified IPs) and malformed or extra listen-port arguments fail startup rather than silently selecting echo mode or dropping bad ports. Secure startup resolves the default state directory identically in its preflight and key-store setup, using `%ProgramData%\\Balancify` on Windows unless overridden. Relay idle-session sweeps and stats now use a monotonic 10-second cadence and run on socket timeouts, so stale sessions expire even when traffic stops. A relay updates a session's peer route only after an authenticated, non-replayed datagram, allowing NAT rebinding without letting unauthenticated traffic redirect replies. If the per-session upstream socket cannot be created or the handshake response cannot be sent, the newly allocated session is removed before peer mappings are installed.
- **Key management**: static keypair derives public, ephemeral zeroized on drop, pinned keys pin/unpin, OS RNG distinct, memory store generates/remembers, file store roundtrips and rejects corrupt. File writes use unique `create_new` sibling temporaries, 0600 mode at creation on Unix, sync-before-rename, and a symlink-regression test; Windows builds enable DPAPI by default and test migration of legacy raw keys. Plaintext buffers and temporary key copies are zeroized after use.
- **Replay protection** (Sec.11.4): new ephemeral not replay, same within window is replay, expired not replay, capacity evicts oldest, different ephemerals not replay (5 tests)
- **Key-update derivation only; live rekey remains pending** (Sec.11.3): crypto tests cover deterministic one-way derivation and per-direction transport-key derivation. The relay has no authenticated key-update/ack exchange, so service thresholds now mark `update_required` and emit a support-bundle warning instead of rotating only the client's ciphers. A secure peer regression verifies traffic remains decryptable after the threshold. Coordinated live rekey, its packet/time acceptance limits, and recovery behavior remain unimplemented.
- **Zeroize**: ephemeral secrets zeroized on drop, replaced cipher keys are zeroized when their cipher objects drop, and plaintext key-store buffers plus returned-secret copies are cleared after use; `x25519-dalek` has `zeroize` enabled and `zeroize` is pinned.
- **Abuse controls + rate limiting (relay)**: global cap 1024 sessions, per-IP 8, aggregate handshake token bucket (burst 200, refill 100/s) plus 10/min/IP, bounded per-IP limiter state, per-session token bucket 100 Mbit/s + 10k pps, stats, sweep old entries.
- **Rate limiting service egress**: TokenBucket rate_bps + burst, try_consume, delay_for, RateLimiter per-uplink, default 1 Gbps/1MB, set_uplink_rate, try_send wired into send_app_packet -> Hold on limit (3 core tests + 1 service test)
- **Tampered input refused** (Sec.9.1b): under real AEAD, flipping any bit of frame's body or tag is refused and counted, nothing reaches inner stack (tunnel + service tests)
- **Fuzz gate over untrusted-input paths** (Sec.4.7.4): 6 seeded, dependency-free generators (20k rounds each for datagram and IPC-frame loops): no panic, no invented payload, session and hold caps bound memory, length checks hold, replay cannot manufacture delivery
- **Wintun fallback exception** (Sec.11.2): feature wintun-fallback, exception file check, raw FFI placeholder, flow-level only, must be retired next minor release, audit allows only when exception file exists (ADR-0009)
- **ETW logging + support bundle redacted** (Sec.8.2, Sec.9.2): Windows ETW EventRegister/EventWrite sink with a stable provider GUID, event IDs 100-600, bounded UTF-16 payload, and stderr fallback off Windows; actual trace collection/decoding remains unvalidated and no provider manifest is installed; ETW failover messages omit relay endpoints. UplinkDiag cwnd/in_flight and CongestionDiag loss/ecn/delay+paths+per_path are included in support-bundle JSON, which escapes strings and is exported through IPC v1 opcode 11; it never includes the configured relay endpoint, reporting only `relay_configured` plus aggregate failover counts.

## Remaining for Phase 4 / G3

- **Driver packaging**: bundle self-contained .NET 10 + WinAppSDK runtimes, transactional installer with atomic rollback, clean-machine offline test per `clean-machine-test.md`, SPDX 2.3 and 3.0.1 sidecars
- **HVCI readiness trio**: Driver Verifier with code-integrity, HLK HVCI readiness test, run on VBS/Memory-Integrity machine (S15)
- **SBOM/VEX S13**: CI generates SPDX 2.3 and SPDX 3.0.1 JSON-LD inventories from the locked production graph, validates SPDX 3.0.1 with the official JSON Schema + SHACL gate, and publishes both as run artifacts. Reviewed VEX and clean-machine installer validation remain pending; no vulnerability-status claims are made.
- **Cargo.lock**: committed and checked by `tools/ci/audit-deps.sh`; regenerate only when the pinned dependency set intentionally changes.
- **Real netem S2c**: replace simulated rig with `tools/lab/netem-rig.sh` profiles, record 10 reps median/p95/spread per Sec.10.1 — harness exists, real Rig B pending
- **Throughput rows on Rig B**: re-run Sec.10.3 aggregate/single-flow/failover with pacing enabled and secure mode, measure added delay and CPU/Gbit/s via crypto-bench + ETW — the local synthetic benchmark is not network evidence; real Rig B results pending
- **Client and service lab binaries + GUI IPC**: `balancify-client` defaults to an authenticated, pinned Noise_IK identity and fails closed on missing/invalid pins or handshake failure; `balancify-service` now rejects missing relay identities, identity/pin-store errors, malformed key settings, and configured keys that conflict with pins; it filters incoming UDP by the active relay endpoint and propagates send failures. Both require explicit debug-only, loopback-only `--insecure-lab` to use the zero-key test cipher (ADR-0035 and ADR-0038). The client stores identity in absolute per-user state paths and filters post-handshake UDP packets to the configured relay endpoint, rejects duplicate handshake responses, and propagates send failures. Production packet-adapter integration, WinUI 3 shell, and production IPC transport/authentication remain pending.
- **Per-session sequence spaces**: striped Data retransmission and independent FlowData use sequences keyed by session, so sessions do not interfere and FlowData does not create gaps in ordered Data (ADR-0011 / ADR-0029).
- **Flow-level ACK and repair**: wire v2 uses a distinct AEAD nonce-domain `FlowAck` for selective FlowData receipt; service validates session/authentication/replay before crediting bytes to the path that delivered them. Pending payload is byte- and entry-bounded, removed on receipt, explicit path re-key, resume, or rate-limit hold. A lost FlowAck causes one alternate-path FlowData retry; receiver replay protection prevents duplicate delivery and sends another ACK.
- **Driver WDF control device + raw-IP NDIS attributes**: source contains SET_MTU, GET_STATS, INJECT_NBL, SET_QUANTA and length validation. `MiniportInitializeEx` submits registration attributes before revision-2 general attributes; miniport/INF use `NdisMediumIP` and omit Ethernet MAC OIDs. OID handling includes bounded lookahead and packet/byte counters. The INF `Mtu` setting is read at initialization with range validation and a 1440-byte fallback. INJECT_NBL validates IPv4/IPv6 declared lengths and the configured MTU, rejects paused requests, and retains owned buffers until NDIS returns the NBL. MiniportPause waits for active receive-indication calls, returned NBLs, and send callback chains. The unimplemented service transmit path explicitly fails outbound NBLs and counts them as errors. Push run `39799406998` compiled/linked x64 and ARM64 with pinned WDK, verified PE machine types, required mitigation flags, and empty certificate tables, passed INF contract tests, and had signing disabled; this is not runtime or hardware evidence. SET_MTU now accepts only the already-configured MTU and rejects changes until NDIS interface reconfiguration is implemented. SET_QUANTA validates basic request sizing and returns STATUS_NOT_SUPPORTED because no scheduler consumes the weights; the driver remains non-operational with no test-signed install, Driver Verifier, HVCI, VM, or S2b packet-path validation.
